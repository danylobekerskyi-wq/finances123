# Перевірка CryptoBot: Fibonacci scalp

Початкові тести: 76/76. Після змін: 176/176, включно зі 100 новими параметризованими сценаріями (5 груп по 20). TypeScript build успішний. /health повертає ok у paper mode; live та Telegram вимкнено.

Історія: 100 paper-угод, сумарний PnL -182.23 USD; 364 shadow-угоди, -409.83 USD. data/ збережено побайтово. Ці результати не доводять причини збитковості; нову стратегію ще не перевірено на історичних ринкових даних або 100 нових ринкових угодах.

TradingService використовує Fibonacci scalp: висхідний імпульс, відкат 38.2–61.8%, закрита бичача свічка 1M вище попередньої та BULLISH 1H. Стоп 78.6%, попередній максимум обмежує простір до цілі. Збережено перевірки комісій, спреду, незалежної ціни, новин і ризику. Сигнал дійсний 60 секунд. Без підтвердження немає signalId для входу. Прямий evaluateSnapshot підтримує legacy breakout для сумісності.

Адаптація: останні 20 збережених закритих paper-результатів; після щонайменше 10 угод негативне середнє R знижує ризик удвічі. Ризик ніколи не підвищується понад конфігурацію. Пам’ять перечитується з paper-state.json після перезапуску. Це консервативна адаптація, не модель машинного навчання. Історія старої стратегії також впливає на початковий ризик.

Виправлено fail-open для некоректної дати новин, нечислової reference price та невалідного спреду/часу. Нова стратегія перевіряє геометрію свічок і відхиляє NaN.

Запуск: Node >=20; npm ci; npm run build; npm test. Збережіть власний .env локально: його немає в цьому архіві. Для paper-сесії задайте TRADING_MODE=paper, AUTO_LIVE_TRADING=false, ENABLE_LIVE_TRADING=false. Для наступних 100 paper-угод зі збереженою історією 100 угод задайте PAPER_TRADE_TARGET=200; AUTO_PAPER_TRADING=true потребує доступу до біржі, reference та поточної перевірки новин. Не видаляйте data/. Не встановлюйте ціль 100, якщо хочете ще 100: старий цикл уже завершений. Автоматичні ринкові угоди під час цієї перевірки не запускалися.

## Автоматичний час утримання

Для нових paper/shadow позицій бот обирає 3–30 хвилин: ceil(2 × відстань до цілі / ATR(14) на 1M), обмежено цим діапазоном. Це евристичний бюджет часу, не прогноз прибутку. Термін фіксується при відкритті й зберігається разом із позицією. Стоп та ціль мають пріоритет; якщо їх не досягнуто, позиція закривається з TIME_EXIT за поточним bid з комісіями та прослизанням. Вихід виконується при першому успішному опитуванні після дедлайну, лише коли процес працює та отримує котирування. Старі позиції без дедлайну зберігають попередню поведінку. Live-торгівля не отримала часових виходів.

Перевірка оновлення: збірка та 185/185 тестів пройшли, включно зі збереженням дедлайну після перезапуску, межами часу, пріоритетом стопа/цілі та одноразовим закриттям.
